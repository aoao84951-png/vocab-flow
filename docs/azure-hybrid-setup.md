# Azure + Google 음성 연결

구현된 코드는 연결 전 Google을 유지합니다. Azure를 활성화하려면 아래 설정이 필요합니다.

1. 단어장 전용 Azure Speech 리소스를 **Free F0**로 만듭니다. S0로 업그레이드하지 않습니다. 다른 앱/Speech Studio에서 같은 리소스로 생성한 사용량은 앱 장부에 들어오지 않습니다.
2. Supabase SQL Editor에서 `supabase/migrations/202609240001_azure_budget.sql`을 실행합니다.
3. Vercel 프로젝트의 서버 환경변수(Production)에 다음을 설정하고 재배포합니다. 키는 채팅/소스코드에 넣지 않습니다.
   - `AZURE_SPEECH_KEY`: 해당 리소스의 키
   - `AZURE_SPEECH_REGION`: 해당 리소스 지역 코드
   - `AZURE_SPEECH_TIER=F0`: 포털에서 실제 F0임을 확인한 뒤 설정
   - `SUPABASE_SERVICE_ROLE_KEY`: 기존 Supabase 프로젝트 서버 키 (NEXT_PUBLIC 접두어 금지)
4. `/voice-comparison`의 ‘단어장 음성 · 월 사용량’에서 ‘Azure 우선’을 선택합니다. 선택은 브라우저별로 저장되고 사용량/음성 캐시는 서버에서 공유됩니다.
5. 첫 문장을 재생한 뒤 사용량이 증가하고, 같은 목소리로 같은 문장을 재생해도 증가하지 않는지 확인합니다. 다른 기기에서도 동일하게 확인합니다.

## 보호 동작

- UTC 월 단위 500,000자 보호 예산. PostgreSQL 조건부 UPDATE로 요청 전에 원자적으로 예약합니다.
- SSML 전체와 CJK 가중치를 포함한 보수적 집계이므로 Azure 실제 청구량보다 먼저 제한될 수 있습니다. Azure 청구 API와 동기화된 숫자가 아닙니다.
- 실패/타임아웃도 이미 합성되었을 가능성이 있어 예약을 돌려주지 않습니다.
- DB 읽기/예약 오류, 미연결, Azure API 제한/오류는 Google 폴백. F0 리소스 자체 제한이 별도로 적용됩니다.
- 안내창은 같은 브라우저 세션에서 사유별 월 1회 표시됩니다. 저장된 Azure 음성은 한도 후에도 사용 가능합니다.
- 비교 페이지 Azure 생성도 같은 장부를 씁니다. 비교 실패 시 Google을 Azure로 표시하지 않고 오류를 표시합니다.
- 오디오는 Supabase DB에 저장합니다. DB 저장공간 한도는 별도이며, Google 자체 무료 한도도 별도입니다.
- 키 교체로 다른 Speech 리소스로 옮겨도 같은 월 장부를 유지합니다. 한도 해제를 위해 장부를 지우지 마세요.

## 연결 전 검증 한계

Azure 키와 서버 DB 키 없이 실제 과금 계량/DB 동시 실행/음성 재생을 확인할 수 없습니다. 자동 테스트는 서버 실패 시 Azure 호출 차단, 한도 초과 차단, 캐시 재사용, 클라이언트 폴백 분리를 검증합니다.
